จำลองและเปรียบเทียบ FCFS, SJF แบบ Non-preemptive และ Round Robin
โดยใช้ชุด Burst Time เดียวกัน แสดงผลเป็นตารางและแผนภาพลำดับการทำงาน

2. ไฟล์และวิธีเปิด
- CPU Scheduling Simulator.html: รวม HTML, CSS และ JavaScript ไว้ในไฟล์เดียว
- README.txt: คู่มือฉบับนี้
ดาวน์โหลดทั้งสองไฟล์ไว้ในโฟลเดอร์เดียวกัน หากเป็น ZIP ให้แตกไฟล์ก่อน
ดับเบิลคลิก CPU Scheduling Simulator.html หรือคลิกขวาแล้วเลือกเปิดด้วย Google Chrome
หรือ Microsoft Edge ไม่ต้องติดตั้งแพ็กเกจหรือเริ่มเซิร์ฟเวอร์
เบราว์เซอร์ต้องเปิดใช้งาน JavaScript โปรแกรมไม่เรียกใช้ไลบรารีภายนอก

3. วิธีใช้
1) กรอกจำนวนโปรเซส 1–100 ระบบสร้างชื่อ P1 ถึง Pn
2) กรอก BT ของแต่ละโปรเซสเป็นจำนวนเต็ม 1–1,000
   หรือกด “สุ่มแล้วดูผล” เพื่อสุ่ม BT ระหว่าง 1–10 และคำนวณ
3) ตั้ง Quantum ของ RR เป็นจำนวนเต็ม 1–1,000,000 ค่าเริ่มต้นคือ 2
4) กด “คำนวณผล” เพื่อคำนวณทั้งสามอัลกอริทึมด้วยข้อมูลเดียวกัน
5) กดบัตร FCFS, SJF หรือ RR เพื่อดูตารางและลำดับการทำงาน
เมื่อแก้ข้อมูล ผลเดิมจะถูกซ่อน ต้องกดคำนวณอีกครั้ง
ปุ่ม “ใช้ตัวอย่าง” คืนค่า BT เป็น 5, 3, 1 และ Quantum เป็น 2

4. เงื่อนไขและหลักการ
- ทุกโปรเซสมี AT = 0 ลำดับเริ่มต้น P1 ถึง Pn
- ใช้ CPU เดียว ไม่มีช่วงรอ I/O และไม่คิดเวลาเปลี่ยนโปรเซส
- FCFS: ทำตามลำดับ P1 ถึง Pn จนแต่ละงานเสร็จ
- SJF: เรียง BT จากน้อยไปมาก ทำจนเสร็จโดยไม่แย่ง CPU
  เมื่อ BT เท่ากัน ใช้ลำดับ P เดิม
- RR: ให้ CPU ไม่เกิน Quantum ต่อรอบ งานที่ยังไม่เสร็จต่อท้ายคิว
- ST คือเวลาที่ได้รับ CPU ครั้งแรก CT คือเวลาที่ทำงานเสร็จ
- TAT = CT - AT ซึ่งกรณีนี้เท่ากับ CT
- WT = TAT - BT
- AVG WT = ผลรวม WT / จำนวนโปรเซส
ตารางแสดง Process, AT, BT, ST, CT, TAT และ WT
Gantt Chart แสดงสูงสุด 200 ช่วงแรก แต่ตารางและค่าเฉลี่ยคำนวณครบทุกช่วง

5. โครงสร้างโค้ด
ส่วน style: รูปแบบหน้าจอและการรองรับจอขนาดเล็ก
สคริปต์ส่วนคำนวณ:
- positiveInteger: ตรวจจำนวนเต็มบวกและขอบเขต
- makeProcesses: สร้างข้อมูลโปรเซสชุดใหม่
- nonPreemptive, fcfs, sjf: คำนวณ FCFS และ SJF
- roundRobin: จัดคิว RR และบันทึก ST เฉพาะครั้งแรก
- finish: สรุป TAT, WT และ AVG WT
- compare: คำนวณครบทั้งสามวิธีด้วย BT ชุดเดียวกัน
สคริปต์ส่วนหน้าจอ:
- buildInputs: สร้างช่อง BT
- calculate: อ่านข้อมูล ตรวจสอบ และเรียกคำนวณ
- renderTable, renderTimeline, renderMethodCards: แสดงผล

6. ตัวอย่างคำนวณมือเพื่อตรวจสอบ
กำหนด P1 BT=5, P2 BT=3, P3 BT=1 ทุกตัว AT=0 และ Quantum=2

FCFS: P1(0–5), P2(5–8), P3(8–9)
Process  AT  BT  ST  CT  TAT  WT
P1        0   5   0   5    5   0
P2        0   3   5   8    8   5
P3        0   1   8   9    9   8
AVG WT = (0+5+8)/3 = 4.33

SJF: P3(0–1), P2(1–4), P1(4–9)
Process  AT  BT  ST  CT  TAT  WT
P1        0   5   4   9    9   4
P2        0   3   1   4    4   1
P3        0   1   0   1    1   0
AVG WT = (4+1+0)/3 = 1.67

RR Quantum=2:
P1(0–2), P2(2–4), P3(4–5), P1(5–7), P2(7–8), P1(8–9)
Process  AT  BT  ST  CT  TAT  WT
P1        0   5   0   9    9   4
P2        0   3   2   8    8   5
P3        0   1   4   5    5   4
AVG WT = (4+5+4)/3 = 4.33
ตัวอย่าง P2: TAT = 8-0 = 8 และ WT = 8-3 = 5
ค่าเฉลี่ยแสดงปัดเป็นทศนิยมสองตำแหน่ง

ชื่อไฟล์สำหรับส่งที่ผู้จัดทำกำหนดคือ CPU Scheduling Simulator.html
ควรใช้ไฟล์ฉบับเดียวกันนี้ในการเปลี่ยนชื่อและจัดส่ง

กรณีที่ 1: BT 5,3,1 และ Quantum=2 — ผ่าน
เปิดดูตาราง FCFS, SJF และ RR ครบทั้งสามวิธี
AT=0 ทุกแถว ค่า ST, CT, TAT และ WT ตรงกับตัวอย่างคำนวณในข้อ 6
AVG WT: FCFS=4.33, SJF=1.67, RR=4.33
ลำดับใน Gantt Chart ตรงกับการคำนวณ

กรณีที่ 2: ตั้งจำนวนโปรเซส 5 แล้วกดสุ่ม — ผ่าน
BT ที่สุ่มได้จริงตามลำดับ P1–P5: 10,7,10,9,4
Quantum ขณะทดสอบ: 1
หน้าจอแสดง AVG WT: FCFS=18.00, SJF=13.00, RR=25.40
เปิดตรวจตาราง RR พบครบ P1–P5 ดังนี้:
Process  AT  BT  ST  CT  TAT  WT
P1        0  10   0  39   39  29
P2        0   7   1  30   30  23
P3        0  10   2  40   40  30
P4        0   9   3  38   38  29
P5        0   4   4  20   20  16
ผลรวม BT = 40 ตรงกับเวลาเสร็จของโปรเซสสุดท้าย
TAT=CT และ WT=TAT-BT ครบทุกแถว
AVG WT = (29+23+30+29+16)/5 = 25.40
สำหรับชุดสุ่มนี้ ตรวจตารางรายโปรเซสของ RR และค่าเฉลี่ยทั้งสามวิธี
ไม่ได้เปิดตรวจตารางรายโปรเซสของ FCFS และ SJF ในชุดสุ่ม

กรณีที่ 3: BT 5,3,1 เดิม เปลี่ยน Quantum จาก 2 เป็น 1 — ผ่าน
ผล RR Quantum=1 ที่แสดงจริง:
Process  AT  BT  ST  CT  TAT  WT
P1        0   5   0   9    9   4
P2        0   3   1   7    7   4
P3        0   1   2   3    3   2
AVG WT = (4+4+2)/3 = 3.33
เมื่อ Quantum=2 ได้ AVG WT=4.33
แสดงว่าการเปลี่ยน Quantum มีผลต่อลำดับการทำงานและเวลารอ

การตรวจข้อมูลผิดผ่านหน้าจอ — ผ่านในกรณีต่อไปนี้
- เพิ่มเป็น 5 โปรเซสโดยเว้น BT ของ P4 และ P5 ว่าง:
  แจ้ง “ยังไม่ได้กรอกเวลาของ P4 ใส่ตัวเลขก่อนนะครับ”
- Quantum=0: แจ้งว่าต้องเป็นจำนวนเต็มตั้งแต่ 1 ถึง 1,000,000
- BT ของ P1=1.5: แจ้งว่าต้องเป็นจำนวนเต็มตั้งแต่ 1 ถึง 1,000
- BT ของ P1=-1: แจ้งข้อผิดพลาดเช่นเดียวกัน
- จำนวนโปรเซสว่าง: แจ้ง “ยังไม่ได้กรอกจำนวนงาน ใส่ตัวเลขก่อนนะครับ”
- จำนวนโปรเซส=0: แจ้งว่าต้องเป็นจำนวนเต็มตั้งแต่ 1 ถึง 100
เมื่อข้อมูลผิด หน้าจอไม่แสดงตารางผลเก่าค้างเป็นผลใหม่
หลังทดสอบ กด “ใช้ตัวอย่าง” คืน BT=5,3,1 และ Quantum=2 ได้ตามปกติ

9. การใช้ AI อย่างโปร่งใส
ข้อมูลต่อไปนี้อ้างอิงเฉพาะการใช้งานจริงในบทสนทนานี้:
- ให้ ChatGPT ตรวจโค้ดเทียบข้อกำหนดโครงงานและตรวจส่วนคำนวณ
- AI พบว่าตารางยังไม่มีคอลัมน์ AT
- ให้ AI เพิ่มคอลัมน์ AT โดยแสดงค่า 0 ทุกโปรเซส
- ให้ AI ช่วยจัดทำ README และตัวอย่างผลที่ใช้ตรวจสอบ
- ให้ ChatGPT ทดสอบผ่านหน้า Safari และ Google Chrome และบันทึกผลจริงลง README
หากใช้ AI ในการพัฒนาก่อนหน้านี้ ให้เพิ่มเติมเครื่องมือ ขั้นตอน และ Prompt จริง

ตัวอย่าง Prompt จริง:
1) “ตรวจสอบงานให้หน่อย” พร้อมข้อกำหนดและไฟล์โปรแกรม
2) “เพิ่มคอลัมน์ AT ในตาราง ใส่ 0 ทุกโปรเซส ให้ครบตามโจทย์ทำ”
3) “ข้อมูลส่วนตัวไว้เดี๋ยวค่อยกรอก”
4) “ทดสอบไฟล์ให้หน่อย”
5) “บันทึกผลทดสอบลง README”

ตัวอย่างการแก้โค้ดโดย AI:
เพิ่มหัวคอลัมน์ ["เวลามาถึง", "AT"]
และเพิ่ม 0 ก่อน BT ในชุดข้อมูลของแต่ละแถว:
[0, p.bt, p.st, p.ct, p.tat, p.wt]

วิธีตรวจผลจาก AI:
- เทียบตารางกับการคำนวณมือในข้อ 6
- เปิดโปรแกรมและตรวจว่า AT=0 ทุกแถวในทั้งสามอัลกอริทึม
- ทดสอบข้อมูลผิดและกรณีทดสอบทั้งสามแบบ
- สมาชิกต้องอ่านโค้ด อธิบายการทำงานและแก้ไขส่วนที่รับผิดชอบได้
เก็บภาพ Prompt คำตอบ และการตรวจผลจริงไว้ใช้ในวิดีโอเบื้องหลัง AI
